# IHVA PARFUM — интернет-магазин парфюмерии

Рабочий мини-магазин по утверждённому дизайну (чёрный/графит/золото, Cormorant Garamond + Manrope):
каталог с поиском и фильтрами, страница аромата с выбором объёма, корзина, заявка без онлайн-оплаты
и уведомление менеджеру в Telegram-бот.

Стек: **Node.js ≥ 22.13 без внешних зависимостей** (встроенный `node:http`, `node:sqlite`, `fetch`),
на клиенте — нативные ES-модули, без сборки.

## Запуск

```bash
cp .env.example .env     # заполните TELEGRAM_BOT_TOKEN и TELEGRAM_CHAT_ID
npm start                # http://localhost:3000
npm test                 # 16 автотестов серверной части
```

Без токена бота сайт открывается, но кнопка «Оформить заказ» честно сообщит, что приём заявок не настроен.

### Настройка Telegram

1. Создайте бота у [@BotFather](https://t.me/BotFather) (`/newbot`) → получите токен → `TELEGRAM_BOT_TOKEN`.
2. Откройте чат с ботом и нажмите **Start** (или добавьте бота в группу менеджеров).
3. Узнайте `chat_id`: отправьте боту любое сообщение и откройте
   `https://api.telegram.org/bot<ТОКЕН>/getUpdates` — в ответе `message.chat.id` (у групп он отрицательный) → `TELEGRAM_CHAT_ID`.
4. Перезапустите сервер. Оформите тестовую заявку — менеджер получит сообщение.

Токен хранится только в переменных окружения сервера; браузер отправляет заявку на `POST /api/orders`,
сервер сам обращается к Bot API.

### Проверка без настоящего бота

```bash
node scripts/mock-telegram.mjs 8081 &
TELEGRAM_BOT_TOKEN=1:TEST TELEGRAM_CHAT_ID=1 TELEGRAM_API_BASE=http://127.0.0.1:8081 npm start
curl -X POST localhost:8081/__mode/fail     # имитировать сбой Telegram (ok | fail | reject)
```

## Как это работает

| Шаг | Где | Что происходит |
|---|---|---|
| Данные | `data/products.json`, `data/site.json` | Единый источник: каталог, карточка, корзина и сервер читают одни и те же цены и наличие. |
| Корзина | браузер, `localStorage` | Хранит только `{id, объём, количество}`; цены каждый раз берутся из каталога. Переживает перезагрузку, синхронизируется между вкладками, недоступные позиции убираются. |
| Заявка | `POST /api/orders` | Сервер валидирует поля, **пересчитывает сумму по своему каталогу** (цены/названия от клиента игнорируются), сохраняет заявку в SQLite, затем шлёт сообщение в Telegram. |
| Успех | экран «Заявка принята» | Показывается только после ответа сервера `200`, т.е. когда заявка сохранена **и** доставлена менеджеру. Корзина очищается в этот же момент. |
| Сбой | тост «Заявка не отправлена» + «Повторить» | Telegram недоступен/не настроен/отклонил запрос → успех не показывается, корзина и форма сохраняются. Повтор использует тот же `clientOrderId`, поэтому дублей заявок и сообщений нет. |

Номер заявки: `IH-ГГММДД-NNNN` (счётчик за день), как в макете.

### Безопасность

- Токен только в env сервера; в клиентский код, HTML и репозиторий не попадает (`.env` в `.gitignore`), из ошибок вырезается.
- Серверная валидация (имя, телефон РФ → `+7 XXX XXX-XX-XX`, город, способ связи, количество 1–10, ≤30 позиций, комментарий ≤500).
- Антиспам: лимит на IP и на телефон, honeypot-поле, лимит тела запроса 16 КБ, идемпотентность по `clientOrderId`.
- Сообщение в Telegram экранируется (HTML), в него не попадают IP, User-Agent и прочие лишние данные.
- CSP без inline-скриптов, `nosniff`, `frame-ancestors 'none'`; статика отдаётся только из `public/`.

### Недоставленные заявки

Заявка сохраняется до отправки в Telegram. Если уведомление не ушло (а покупатель не нажал «Повторить»):

```bash
npm run orders                    # список
npm run orders -- --pending       # только недоставленные
npm run orders -- --resend        # отправить их менеджеру повторно
```

## Развёртывание

Любой хостинг с Node.js и **постоянным диском** (VPS, Render/Railway/Fly с volume). SQLite-файл — `DATABASE_PATH`.
Переменные: см. `.env.example`. За nginx/Cloudflare выставьте `TRUST_PROXY=1`, чтобы лимиты считались по реальному IP.
Серверless-хостинги без диска (Vercel/Netlify) не подходят без замены хранилища.

Резервная копия заказов — файл `storage/orders.db` (режим WAL: копируйте вместе с `-wal`/`-shm` или через `sqlite3 .backup`).

## Что нужно заполнить владельцу (в макете этих данных не было)

В `data/products.json`:

- **Цены.** Из макета взяты: все цены Xerjoff Purple Accento (3/5/10/30/50 мл), Mancera Red Tobacco 3 и 5 мл и цены «от» за 3 мл
  для остальных. Остальные объёмы получены по той же лестнице, что у Xerjoff (×1,6 / ×1,8 / ×2,8 / ×7,5 / ×11,6) и помечены
  `"priceSource": "estimate"` — **подтвердите или исправьте перед запуском**.
- **Наличие по объёмам** (`available`) — по макету; Hormone Paris — нет в наличии.
- **Ноты, сезоны, стойкость, «для кого», описание бренда** — в макете есть только для Purple Accento. Для остальных блоки
  скрыты (`notes`, `seasons`, `longevity`, `audience`, `brandInfo` = `null`), описание — нейтральное. Заполните — блоки появятся сами.
- **Фото**: нет у K by Dolce & Gabbana и Hormone Paris (показывается нейтральная заглушка). Положите файл в
  `public/images/products/<id>.jpg` и укажите путь в поле `image`.
- **Telegram-ссылка магазина** — `PUBLIC_TELEGRAM_URL` (в макете «[ссылка на Telegram]»). Пока пусто — кнопки Telegram скрыты.
- **Контакты** (WhatsApp, Instagram) — `data/site.json`.

```
server/    app.js (маршруты, статика, шаблоны) · orders.js (приём заявки) · telegram.js · validate.js
           products.js (расчёт цены) · db.js (SQLite) · ratelimit.js · config.js
pages/     HTML страниц + partials (шапка, подвал, мобильное меню)
public/    css/design.css — дизайн-система из макета без изменений; css/site.css — состояния и адаптив
           js/core.js (данные, корзина, тосты) · home|catalog|product|cart|checkout.js · fonts · images
data/      products.json · site.json
scripts/   orders.mjs · mock-telegram.mjs · gen-products.mjs (однократный генератор products.json)
test/      api.test.js
```
